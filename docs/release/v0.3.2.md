# WoW Sync v0.3.2 (pre-release)

An **unsigned Windows x64 preview**. **Update every computer in the group to
v0.3.2**: computers on different versions are now flagged, and the fixes below
only help the computer that runs them.

## Fixed

- **Clicks are answered at once.** A sync pass no longer makes Decide, Pause,
  Resume, Export or other buttons wait for it to finish. A pass yields to a
  waiting click, answers it, then continues; the log says
  `sync pass paused after N ms to answer a command`.
- **Pause and Resume register once.** The button shows "Pausing…" or
  "Resuming…" until the change is applied, and repeat clicks are ignored
  instead of being applied later in a burst. Group actions (Decide, Export and
  the like) show "Working on it…" and ignore a second click until the first
  has a result.
- **Every action result is logged**: accepted or refused, why, and a short
  record id. Never a path, add-on name or file content.
- **Passes are fast after the first.** WoW Sync remembers the hash of each
  unchanged add-on file (size and modified time unchanged, and not modified in
  the last few seconds) in a per-install cache in its local state folder, so a
  pass no longer re-reads every file. On a 34,000-file add-on set a
  full read took about 6.9 s (warm disk) and an unchanged pass now about
  0.15 s. A changed file is always re-read. A damaged cache is ignored and
  rebuilt. The cache holds no file contents and is never shared.
- **Settings → Check all files** forces one pass that ignores the cache, for
  when you want every file re-read.
- **An honest "waiting" headline.** An add-on whose files have not arrived no
  longer says "Waiting for Dropbox to finish downloading" for hours. It names
  the computer that has not finished sharing it ("Waiting for LENOVOFISH to
  finish sharing Questie"), and after 30 minutes says that computer has not
  finished and to open WoW Sync on it. A pending decision is no longer hidden
  behind this message.
- **Version differences are shown.** A computer's page says when that computer
  runs a different WoW Sync version than this one.

- **Your saved setup is never hidden on start.** A computer that is already set
  up opens straight to the main window ("Checking add-ons…") instead of the
  setup pages while the first check runs.
- **An internal error no longer silences syncing.** If a check hits an internal
  error, the window says so, names the step, keeps Pause, Quit and Export
  diagnostics working, and tries again: after 5 minutes, then 10, then 20 between\n  tries (see Retries below).
- **No second setup by accident.** Finishing setup on an already set-up
  computer is refused with a plain message and changes nothing.
- **Diagnostics list peer versions.** Each computer row shows its WoW Sync
  version.

- **Lost setup is reported, not hidden.** If a saved setup exists but its
  enrollment cannot be loaded, the window says so and offers setup again
  instead of showing "Checking add-ons…" for ever. Nothing is deleted or
  enrolled twice.
- **Retries are real.** After an internal error, or if the sync service cannot
  open, WoW Sync reopens it from what is saved on disk (not half-updated
  memory) and retries after 5 minutes, then 10, then 20 minutes between tries.
  Pause, Quit and Export diagnostics keep working meanwhile.
- **Provider and variant problems stay visible** while "Checking add-ons…" is
  shown.
- **The hash cache is bounded** (about 12 MiB, far under the background memory
  limit) and caches of installs no longer in use are removed.
- **Conflicting choices no longer crash sync.** Two computers that each kept a
  different copy now raise one decision instead of an internal error (the
  RYZENFISH crash). A choice that is out of date, for example after another
  computer already settled it, is refused with "this choice is out of date, the
  list was refreshed". Resume versus Keep conflicts raise a decision.

- **The quit confirmation is always visible.** "Quit when safe" / "Keep
  running" now sit above the scrolled page instead of inside it, so they are
  on screen even when Settings is scrolled to the bottom.

## Known limits

- Retries: the internal-error retry is covered by an automated test; the retry
  after a failure to open the service is implemented (same 5/10/20 minute
  schedule, and the error is shown) but has no automated test.
- The 30-minute timer for the waiting headline restarts when WoW Sync restarts.
- A click during the very first upload of a large add-on set is answered when
  the current upload step finishes, which can take over a minute; once files are
  shared, clicks are answered in about two to three seconds on a 3 GB set (see
  the run evidence for measurements and the remaining cause).
- The decision and choice fixes of this release are described in the
  R9-decide notes.
- Live GUI behaviour of the quit confirmation and memory on a real 3 GB tree
  were checked by the independent reviewer, not by this change's tests.
