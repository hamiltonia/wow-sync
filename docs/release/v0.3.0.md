# WoW Sync v0.3.0 (pre-release)

An **unsigned Windows x64 preview**. It is a pre-release for testing, not a
finished product. Back up your `Interface\AddOns` and `WTF` folders first; that
is advice, not a gate.

## Finds WoW on any drive

v0.2.0 only looked in Program Files and on drives C to F, so a game on, say,
`G:\Games\World of Warcraft` was not found. Setup now looks at:

- the install path that Battle.net itself recorded (read-only, from
  `%ProgramData%\Battle.net\Agent\product.db`);
- the usual Program Files folders;
- four usual folders on every local fixed drive, A to Z:
  `World of Warcraft`, `Games\World of Warcraft`,
  `Program Files (x86)\World of Warcraft` and `Program Files\World of Warcraft`.

Network, removable and optical drives are never touched, so a dead network
drive cannot stall setup. Nothing is written while looking.

## Choose a folder yourself

Step 3 of setup always has **Choose folder…**. When nothing was found it says
so in plain words and asks you to choose the folder where the game is
installed (it contains folders like `_retail_` or `_forever_`). You can pick
the install folder or one of the version folders inside it. A folder that is
not a game install gets a plain explanation that names the folder you chose.

A folder you choose goes through the same game-version and add-on-list
confirmation as one that was found. If Dropbox is not found, step 2 offers
**Choose your Dropbox folder…**; the shared folder is still `WoW Sync` inside
it. A Dropbox folder you choose that Dropbox does not report is accepted with a
warning, because sync only works if every computer uses the same Dropbox folder.
The folder you choose is checked in the background, so a slow or network location
shows "Checking…" instead of freezing the window.

## Large `.toc` files

An add-on folder with a very large `.toc` (for example QuestieDB, 17.6 MB) is now
recognised from the first 256 KiB of its header, so it is recognised like any other
add-on and its settings sync normally, instead of being blocked.

## Add-ons that cannot be recognised

Add-ons whose `.toc` cannot be recognised (none for this game version, several with
no way to tell which applies, only other game versions, or unreadable) now sync by
content and show "Unrecognised: synced by content — <reason>".

When the copies on two computers differ: each computer publishes which copy its
change replaced, so the newest copy wins everywhere; if copies changed
independently or one went back to an older copy, you choose once for that add-on.
Replaced copies are kept for recovery. File times are never used to decide.

Settings of unrecognised add-ons are not synced, because they declare no saved
variables. Folders that are unreadable, unsafe (links), unstable or unsupported are
still not synced, and the reason is shown.

## A log that is on by default

WoW Sync now keeps a diagnostic log without any setup:

`%LOCALAPPDATA%\WoWSync\state\logs\wow-sync.log`

Settings, then Data, then **Open data folder** opens the folder that holds the
`logs` folder. The log rotates at 1 MiB and keeps one older file,
`wow-sync.log.1`. Setting `WOWSYNC_LOG` to a file path before starting the app
still sends the log there instead.

Each line has a UTC time, the process number and a level. It records the start
and version, every place it looked for the game and what it found, the
Dropbox result, setup steps and folder choices, errors, and each add-on that is
blocked or not recognised, with the folder name and the reason only. Your
user folder is written as `~`. It never records add-on files, saved settings,
or account, realm or character names. Please attach it when reporting a problem.

## Still missing

- No installer, no code signing and no macOS binary. Windows SmartScreen will
  warn that the publisher is unknown, as before: choose "More info", then
  "Run anyway", only if you downloaded it from this release and the SHA-256 in
  the `.sha256` file matches.
- The search does not look inside folders beyond the four usual places per
  drive and Battle.net's record. A game kept anywhere else needs **Choose
  folder…**.
- The GUI items recorded as BLOCKED in run-005 are still not verified.
- The Forever `.toc` order has still not been checked in the client (Q-3).
- The earlier known gaps that are not listed as fixed here still apply,
  including the 32 MiB settings size cap and the update notice that ignores
  pre-releases.

## Verifying the download

Compare the SHA-256 of `wow-sync-0.3.0-windows-x64.zip` with the value in
`wow-sync-0.3.0-windows-x64.zip.sha256`:

```powershell
Get-FileHash .\wow-sync-0.3.0-windows-x64.zip -Algorithm SHA256
```
