# Owner and design questions

Part of the [slice design](README.md). Each item is a choice the approved
intent does not settle. "Owner" items change product behavior; "design" items
are engineering defaults the orchestrator may accept.

- An item is **decided** only when the owner (product meaning) or the
  orchestrator (engineering) records it in
  [OWNER-DECISIONS.md](../OWNER-DECISIONS.md) or a run plan.
- An item marked **PENDING OWNER** is **not decided**. Its default is the
  conservative behaviour phase C may build and test, but an acceptance item
  that depends on it is reported as blocked on the owner answer, never as
  passed. Where the default disables a feature (for example Q-77), the
  feature stays disabled on real data until the answer is recorded.
- Other open items: implementers follow the recommended default until a
  decision is recorded.
- Technical caps (engineering defaults that protect the process) and product
  gates (owner-approved values) are kept apart in
  [contracts.md](contracts.md) §8.

## Slice limitations (retry 2)

Narrowed behaviour chosen over added machinery; each needs a later decision
before release.

| Limitation | Q |
|---|---|
| Runs only on installs carrying the synthetic marker | Q-24 |
| Folders with any suffixed toc are never transferred, for every client | Q-3, Q-20 |
| A package whose candidate lacks any group-wide member folder is a decision everywhere, also on computers without the package | Q-2 |
| Every publish re-hashes every referenced existing object | Q-7 |
| Any existing journal blocks all new applies on that computer; `needs_help` is resolved later via GUI | Q-25 |
| A crash after the last commit rename but before `committed` is recorded rolls the package back (new content is re-applied next cycle) | Q-25 |
| Online-only or recall-flagged provider entries (files and directories) are refused, never hydrated | Q-6, Q-23 |
