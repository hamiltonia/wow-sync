# Owner and design questions

Part of the [slice design](README.md). Each item is a choice the approved
intent does not settle. Implementers follow the **recommended default** until
the owner (product meaning) or orchestrator (engineering) records otherwise in
[OWNER-DECISIONS.md](../OWNER-DECISIONS.md) or the run plan. "Owner" items
change product behavior; "design" items are engineering defaults the
orchestrator may accept.

| # | Question | Recommended default | Who | Used in |
|---|---|---|---|---|
| Q-1 | How are folders grouped into one addon package? | Union of shared external id, hard dependency whose stem prefixes the dependent's name, `X_`/`X-` name prefix, and the `Family` edge (prefix without separator, stem ≥ 5 chars, no differing external ids: `Questie`/`QuestieDB` grouped). Over-grouping preferred to mixing parts; edges shown in explanations; a grouping change yields new package hashes (revised in retry 1, M-04) | owner | [domain.md](domain.md) §5 |
| Q-2 | When the winning version of a package lacks a folder this computer has (or vice versa), what happens? | Not installed: the package is `NeedsDecision(PartialCandidate)` and nothing is changed or removed; the decision is shown with folder lists. Removal waits for the uninstall design (revised in retry 1, M-04) | owner | [domain.md](domain.md) §6 |
| Q-3 | For `wowf`, which `.toc` does the client load: `_Forever`, `_Camelot`, plain? | Assume `Forever`, then `Camelot`, then plain; disagreement between Forever and Camelot fails closed as ambiguous. **Needs an owner-run client check** (e.g. a test addon with differing tocs) before release | owner | [domain.md](domain.md) §3 |
| Q-4 | If WoW starts while a package is being committed, roll back or complete? | Neither while WoW runs: stop with **no further game-file change** (no rollback), keep journal and all copies, show "Waiting — will restore after WoW exits". After a fresh not-running observation, roll the package back (`committing`) or verify it (`committed`). The mixed state while WoW runs and the launch-between-check-and-rename window are reported residual races (revised in retry 1, B-01; replaces the earlier "roll back immediately") | owner | [apply.md](apply.md) §2.3, §4 |
| Q-5 | May the app read AddOns and publish while WoW is running? | Yes (reads only; SPEC blocks only game-file changes). Unstable files defer publishing | owner | [apply.md](apply.md) §1 |
| Q-6 | Should the app force-download (hydrate) online-only provider files? | No. Treat them as not yet available and wait; user can make the folder "available offline" in Dropbox | owner | [adapters-api.md](adapters-api.md) §5 |
| Q-7 | Provider storage: per-file blobs, no compression, no garbage collection in the slice? | Yes for the slice; GC/retention of unreferenced blobs must be designed before release (R-14) | design | [publication.md](publication.md) §5 |
| Q-8 | Provider-tier test data size and location | Synthetic only, ≤ 50 MB per run, under `D:\Dropbox\Gaming Sync\WoW Sync Test\<run-subdir>`, removed afterwards | owner | [tests.md](tests.md) §4 |
| Q-9 | Where do staging, journals and recovery points live? | `<variant>\.wowsync\` (same volume as AddOns, outside the AddOns folder so WoW does not see them) | owner | [apply.md](apply.md) §2 |
| Q-10 | Are semver-like, dotted-numeric and git-describe labels one comparable family? | Yes (spike data shows authors move between them); unknown pre-release words stay ambiguous | owner | [domain.md](domain.md) §4 |
| Q-11 | Must `.product.db` also agree for variant validation? | Not in the slice (binary format); `.flavor.info` + `.build.info` must agree. Revisit if a client is found where they diverge | design | [domain.md](domain.md) §2 |
| Q-12 | Which product codes are "known"? | Only `wowf` (Forever). Every other client, including retail/classic, goes through guided unfamiliar-client confirmation until a profile is verified | owner | [domain.md](domain.md) §2 |
| Q-13 | Record compatibility | Unknown fields ignored within a schema major; unknown major refused and shown as "written by another app version" | design | [publication.md](publication.md) §2 |
| Q-14 | Non-ASCII addon folder/file names | Unsupported in the slice (listed, never transferred). Needs a Unicode normalization/case-fold design before release | owner | [domain.md](domain.md) §5 |
| Q-15 | Quiescence window | Files modified in the last 2 s, or changed while hashed, make the folder unstable for this cycle | design | [apply.md](apply.md) §5 |
| Q-16 | Processes the app cannot inspect (access denied) | **Block** (`Unknown`) when an uninspectable process's executable name is `wow*.exe` or matches an `.exe` in the variant folder; ignore other uninspectable processes but count them in diagnostics. A renamed client outside the variant folder run elevated is not detected (stated limitation). Revised in retry 1 (M-06) from "never block" | owner | [adapters-api.md](adapters-api.md) §6 |
| Q-17 | Windows-only tests are listed under tier `native`, which `verify` does not execute yet | Keep them `native`; R2-check verifies them from the Windows `cargo test` output and records each name as passed/failed; provider tests that print `BLOCKED` are recorded BLOCKED, never passed. A later packet makes `native` executable in xtask | design (orchestrator) | [tests.md](tests.md) §1 |
| Q-18 | Recovery points are local-only (not uploaded) in the slice (P1-map Q2) | Yes; group-wide rollback is out of slice and will need its own design | owner | [apply.md](apply.md) §2 |
| Q-19 | Process model | One process (GUI + background sync thread) for the slice, per S-mem option 1; not a release decision | design | [crates.md](crates.md) §1 |
| Q-20 | Unfamiliar clients: which `.toc` does the client load when suffixed tocs exist? | Unknown without a verified profile, so for unfamiliar clients only folders with a plain toc and **no** suffixed toc are eligible (mapping `validated-plain/1`); other folders are listed as blocked (`UnvalidatedTocMapping`) and never transferred. New in retry 1 (M-02/M-03) | owner | [domain.md](domain.md) §2.1, §3 |
| Q-21 | May an addon version move between computers whose client build differs? | No automatic install: a candidate from a different `build_version` (or different toc mapping) is `NeedsDecision(DifferentClientBuild/DifferentTocMapping)`. Safe but may block during staggered patch days; revisit with an owner-approved compatibility rule. New in retry 1 (M-03) | owner | [domain.md](domain.md) §6 |
| Q-22 | Manual edits that change content but not the version label | Indistinguishable from an author update with the same label: same label + different content is `Ambiguous`; a manual edit that also bumps the label wins as "newer". Stated limitation; no history-based detection in the slice. New in retry 1 (M-03) | owner | [domain.md](domain.md) §4 |
| Q-23 | Which provider reparse states are safe? | Under the provider root only: cloud-file tag family (`0x9000xx1A`) accepted when the entry is hydrated (no RECALL/OFFLINE attributes); online-only refused as not available (Q-6); links, junctions and other tags refused everywhere. Meaning of the observed `PINNED` attribute and online-only behavior are unverified until an owner-prepared online-only file exists (provider test BLOCKED otherwise). New in retry 1 (M-01) | design (owner confirm) | [adapters-api.md](adapters-api.md) §2, §5 |
